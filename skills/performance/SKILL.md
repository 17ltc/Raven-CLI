# Performance

- Define the latency, throughput, memory, startup, or cost target before optimizing.
- Measure a representative baseline and profile before changing implementation.
- Fix the dominant bottleneck first; distinguish algorithmic, I/O, allocation, concurrency, and rendering costs.
- Preserve correctness and observability, and avoid trading a measured problem for speculative complexity.
- Re-run the benchmark and relevant correctness tests after each material optimization.
