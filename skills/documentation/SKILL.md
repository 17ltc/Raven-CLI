# Documentation

- Derive instructions from the current implementation, tests, configuration, and entry points.
- Put the shortest useful path first: purpose, installation, quick start, common workflows, and troubleshooting.
- Keep examples runnable and mark assumptions, platform differences, and required environment variables.
- Document public interfaces, failure modes, security boundaries, and migration notes when relevant.
- Remove stale claims instead of preserving them for completeness.
